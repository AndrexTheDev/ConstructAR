# Testing ConstructAR

Everything in this document has run. Nothing in it is a plan.

The app is verified in seven layers. Each one answers a question the others cannot, and each one
is cheap enough to run on every change — which is the only property that matters, because a test
that is too expensive to run is a document, not a test.

| Layer | Runs in | Proves |
| --- | --- | --- |
| 1. Static gates | `scripts/verify_sources.py` | headers, reflection ban, no hardcoded UI text, every `R.string` exists, six locales agree, XML is well formed, Kotlin brackets balance, no INTERNET permission, no cloud SDK, manifest hardening |
| 2. Site gate | `tools/seo_audit.py` | the six landing pages, their metadata, their structured data, every internal link, the sitemap, robots.txt, the manifest and the 404 |
| 2b. Translation and agreement gates | `tools/i18n_audit.py`, `tools/consistency_audit.py` | no locale is a copy of English ("Export" is German, "Lifetime" is not), no surface mixes address forms ("Sie" in one AR hint, "du" in the next), French and Italian write one style of apostrophe, and the page and the app agree on prices, wallet addresses, languages and version |
| 3. JVM unit tests | `gradle … testDebugUnitTest` | geometry, pricing, licences, storage (round trip, restore, corrupt file, stale temp files, delete), BOM arithmetic, formatting, routing warnings, hit stabilisation, the printed cost block, the exported file names in five languages, the PLY/GLB byte layout, and the WCAG contrast of every theme pair the UI draws text on |
| 4. Host C++ tests | `g++ … tests/host_tests.cpp` | TSDF integration, Surface Nets, pose-graph closure — with `-Werror`, no NDK needed |
| 5. Full build | `.github/workflows/android-build.yml` | `assembleDebug testDebugUnitTest` across five modules, warnings as errors, R8 on the release variant, the licence verifier surviving R8, the arm64 native library inside the APK |
| 6. Human review | a person, a tape measure | ±2 cm on a detected wall; whether a plumber understands the HUD |

## Running it locally

```bash
python3 scripts/verify_sources.py --verbose          # layer 1, no JDK needed
python3 tools/build_site.py && python3 tools/seo_audit.py --verbose   # layer 2
gradle assembleDebug testDebugUnitTest               # layers 3 and 5
```

## What no automated layer can prove

There is no screenshot matrix. It existed during the beta test to answer *"does this screen fit in
Polish?"* without a device farm, and it was deleted when the review ended: its artifacts were never
verifiable from inside the pipeline, so keeping a green job that renders pixels nobody looks at
would have been the illusion of coverage rather than coverage. **Layout and touch behaviour are
checked with a phone in a hand** (`docs/RELEASE_CHECKLIST.md`), and the six locales are held to
their strings by the gates in layer 1 - the string that exists, is translated, and is measured
against its own formatting rules, not the pixels around it.

What *is* asserted about the landing pages is structural and lives in `tools/seo_audit.py`: every
page has exactly one `<h1>` and a description, no image is missing `alt`, every internal link and
fragment resolves, and the six locales carry the same metadata. That is a gate a person can read and
argue with; a golden image is not.

## What is *not* verified

* **ARCore on a device.** No emulator and no physical phone are part of this repository. The AR
  pipeline is unit-tested at the seam (`SurfaceHitResolver`, `HitStabilizer`, `RouteSession`,
  `MetricDepthCalibrator`) and never end-to-end. Nothing here claims otherwise.
* **The measurement claim.** ±2 cm on a detected wall between 1 and 4 m is a design target from
  the accuracy table; `docs/RELEASE_CHECKLIST.md` lists the laser-measure comparison that has to
  happen on real hardware before it can be called measured.
* **The PDF and the GLB on a device.** Both writers are pure Kotlin and are unit-tested for
  structure, but `PdfDocument` is an Android class: the file is produced, never opened, in CI.
* **Anything about a real purchase.** There is no checkout server; the licence flow is tested
  with keys minted by `tools/mint_licence.py`.

## Swept clean

Areas walked end-to-end with **no defect found**, so the next round does not spend its time there
again. Each line names what was read, not what was assumed.

* **AR screen re-entry and anchor lifetime.** `ArMeasureController.release()` runs from the
  screen's `DisposableEffect`, drops every anchor (`ArCoreAnchorFactory.detachAll`), closes the
  monocular depth model and stops the pipeline; `RouteSession` gets a fresh state per entry. No
  path found that leaves anchors or a depth session behind across entries.
* **PLY number formatting.** Every float goes through `String.format(Locale.ROOT, "%.5f", …)` and a
  non-finite value becomes `0.00000`, so a German phone cannot write a comma decimal into an ASCII
  PLY. The comment sanitising is finding 17's.
* **Export file names.** Two rooms exported in the same minute differ by name *and* timestamp in
  the stem, and `createFile` uniquifies a duplicate anyway, so nothing is silently overwritten.
* **A folder deleted after an export.** The app asks for the folder on every export and stores no
  handle, so a deleted folder cannot become a stale permission that fails later.
* **Project creation entry points.** The plan gate lives in `ProjectViewModel.createProject`, the
  only function that inserts a project, so a share intent or a future screen cannot bypass it.
* **Stale mesh export after a licence lapses.** `includeGlb`/`includePly` are `remember`ed *keyed on*
  `entitlements.isPro`, so a lapse resets them to the (false) entitlement rather than leaving a
  paid format ticked.
* **Storage reclaimed on delete.** `ProjectRepository.delete` removes the room's JSON, its draft and
  every photo whose name starts with `<id>__`, and the diary/defect delete paths remove their own
  photo; nothing orphaned in private storage.
* **Run numbering with gaps.** `RouteLabels.next` numbers past the highest number in use and
  loops while the label it builds is already taken, so deleting run #2 of three cannot make the
  next run #3 as well, and a hand-edited label cannot be handed out twice.
* **Deleting the room you are standing in.** The delete confirmation carries the project id, not a
  list position, so a refresh behind the dialog cannot make it delete a different room; the quick
  resume preference is cleared when its room goes, and the open project is dropped from the state.
* **A backup of a room that no longer parses.** `backupEntries` copies every `.json` file byte for
  byte, including one this app can no longer read, so the file that a restore now reports as
  unreadable (finding 55) is still in the backup rather than silently dropped.
* **A licence key pasted out of an e-mail.** `LicenceFormat.split` removes spaces, line breaks and
  carriage returns before parsing, so a key that wrapped over three lines still verifies.
* **Buying during the trial.** `EntitlementRules.decide` returns a live licence before it looks at
  the trial at all, and reports `trialAvailable = false` from then on, so activating a key mid-trial
  cannot be undone by the trial expiring and a second trial cannot be started on top of a paid one.
* **The appendix can always reach its eight photos.** `buildPhotoAppendix` takes the first eight
  of the same order the field book uses, and the screen budget it reads from is twelve - larger, and
  filled in that order - so a photo the page wants is never one the phone did not decode. Marking a
  defect resolved re-sorts the order but not the map, which is a map: nothing is lost.
* **Every other screen scrolls.** `ui/` was walked for `fillMaxSize` columns without
  `verticalScroll` or `LazyColumn`: export, field book, help, materials, paywall and the room screen
  all scroll, the home screen is a lazy list, and the AR screen is an overlay with no scrolling by
  design. Onboarding was the single exception (finding 66).
* **Free-plan promises on the landing pages.** "One room, unlimited routes, CSV and PDF with a
  watermark" was checked line by line against `Entitlements` (`FREE_PROJECTS = 1`,
  `maxRoutesPerProject = MAX_VALUE`, `canExportCsv`, `canExportPdf`, `pdfWatermark = !isPro`), and
  "seven days of Pro" against `Plan.TRIAL(isPaid = true)`.
* **Every write path reports, and what it reports is readable.** After findings 72 and 73 all of
  them were walked again: `mutate` sets `PROJECT_SAVE_FAILED` when `save` returns false, a photo
  copy and the off-screen room write say `PHOTO_SAVE_FAILED`, and the export and the backup map a
  throwable to a sentence (`storageFailureOf`) instead of printing it. Underneath, `SafeFiles`
  writes a temporary, `fsync`s and renames - the previous version deleted the target first, which
  is how a room used to disappear with the battery. Rule 11 keeps a dropped `save()` result from
  coming back.
* **The licence's last valid day.** `LicenceVerifier` accepts while `todayEpochDay <=
  expiresEpochDay` and `EntitlementRules` re-checks the same comparison against the watermark;
  `daysLeft` reaching 0 on that day is harmless because "0 days left" is a *trial* sentence
  (`Plan.TRIAL` only) and the trial's own window is `start..start+6`, where the counter runs 7..1.
  `paywall_active_until` formats the epoch day in **UTC**, so a negative-offset zone cannot print
  the previous day as the last one.
* **PDF pagination.** Every table row, note block, photo cell and the signature block re-checks the
  remaining height before it draws (`y`/`py` against `pageHeight - FOOTER_HEIGHT`) and starts a new
  page with the section title repeated; the photo grid breaks whole rows, so a caption cannot be
  printed without its picture. The photo appendix is always its own page.
* **Icon-only controls.** Every `IconButton` in `ui/` carries a `contentDescription` resolved from
  `strings.xml` (back, export, help, rename, delete, photo, defect toggle, clock delete, both AR
  buttons). The only `null`s are decorative icons inside rows or buttons that already carry text
  (`GloveControls`, the plan cards, the lock and check marks), which is what `null` is for.
* **One total length.** `ProjectRecord.totalLengthMeters` sums `polylineLengthMeters`, which adds the
  closing segment exactly when `closedLoop && nodes.size > 2` - the same rule
  `PolylineMetrics.measure` applies - so the home list, the protocol summary and the bill of
  materials cannot disagree about a closed ring.
